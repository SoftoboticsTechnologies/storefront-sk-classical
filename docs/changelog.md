# Changelog

Concise history. Not a full commit log — one line per meaningful change.

## 2026-09-04
- CI: enabled, then same-day disabled (commented out), the CloudFront cache-invalidation step in the S3 deploy workflow (`.github/workflows/deploy-s3.yml`).

## 2026-09-03
- Shipment tracking: added tracking fields to `features/account/graphql.ts`, surfaced on `account/routes/orders/order-detail.tsx`; translations added across `en`/`de`/`hi`/`tel`. Minor related changes to `checkout-flow.tsx`/`shipping-address-step.tsx`.
- Static-export migration (superseding the 2026-09-02 SSR→SSG/ISR entry below — `partialPrefetching`/`cacheComponents` were removed): `next.config.ts` switched to `output: 'export'` (full static export, S3+CloudFront, no Node/server runtime), `trailingSlash: true`, `images.unoptimized: true`. Cart, checkout, auth, and currency resolution moved from Server Actions/cookies to client-side calls against Vendure directly (`platform/vendure/channel-client.ts`). `product/[slug]` became `product/[slug]/[[...variant]]` (optional catch-all for a variant SKU) so each non-default variant gets its own statically prerendered page with a real baked-in price (`features/products/data.ts#getProductVariantParams`). Introduced `features/search/search-params-sync.tsx` so no component calls `next/navigation`'s `useSearchParams()` directly; `collection-results.tsx`/`product-card.tsx`/`product-info.tsx`/`product-price-client.tsx` updated to take build-time initial data superseded by a live client fetch. Root redirect and `scripts/write-root-redirect.mjs` updated for trailing-slash static hosting compatibility. `next/link` prefetch disabled globally to work around a Next.js static-export bug. See `docs/decisions.md` for the full rationale; `docs/architecture.md`'s "Rendering strategy" section documents the resulting model.
- Env/deploy: updated `.env.production` and `.github/workflows/deploy-s3.yml` for static-site-generation output and S3 hosting.

## 2026-09-02
- SSR → SSG/ISR for catalog routes (product/collection): added `generateStaticParams` to `features/products/routes/page.tsx` (backed by new `features/products/data.ts` `getPopularProductSlugs`, reusing the existing `SearchProductsQuery` — no new GraphQL op) and `features/collections/routes/page.tsx` (backed by existing `getTopCollections`). Enabled `partialPrefetching: true` in `next.config.ts` alongside the already-on `cacheComponents`. Known slugs now serve as fully static/ISR pages (`x-nextjs-prerender: 1` verified against a production build/start); unknown slugs still render via the existing route-level `loading.tsx` App Shell and upgrade to static after their first visit. Cart, checkout, account, auth, sign-in, and search intentionally do **not** get `generateStaticParams` and remain dynamic per `docs/decisions.md` — they depend on cookies/Server Actions that cannot be prerendered. Currency-dependent pricing is unaffected: `getActiveCurrencyCode()` still resolves per request and streams into the prerendered shell exactly as before. Verified with `check-types`, `lint`, `test` (3 pre-existing Windows-only upgrade-tooling test failures, unrelated, reproduced on `main` before this change), and a full `next build` + `next start` (standalone) smoke test against real product/collection slugs.

## 2026-08-31
- Homepage redesign (task 2 of the UI redesign): recomposed products-as-hero, editorial homepage — `AnnouncementBar` (site-wide) → visual `Hero` (real collection image/name, no fabricated shipping claim) → `CategoryDiscovery` (quick-nav strip) → `FeaturedProducts` → `EditorialBanner` → `TrendingProducts` (sourced from a second real collection, no fake "new" sort) → `ShopByCategory` (incl. subcategories) → `BenefitsSection` (restyle of prior "Why Shop With Us") → `CtaBanner` (promotional, links to `/register`, no email form — no subscription backend exists). `GetTopCollectionsQuery` top-level items extended with `featuredAsset`/`description` (additive). `features/products/featured-products.tsx` generalized to accept `collectionSlug` (was hardcoded `"electronics"`) and now exports both `FeaturedProducts` and `TrendingProducts`. No commerce/cart/checkout/auth logic touched; `check-types`, `lint`, and `build` all pass; manually verified EN/DE homepages render all sections with correct translations.
- Docs: created `CLAUDE.md`, `docs/commerce.md`, `docs/ui-system.md`, `docs/decisions.md`, `docs/changelog.md` as persistent project memory ahead of the premium-ecommerce UI modernization (existing `docs/architecture.md` and `docs/adr/` kept as-is). No source changes.
- Fixed faceted search: multi-select within one facet group now uses OR (was incorrectly AND'ing all selected values across groups, producing zero results).
- Header/navigation modernization (task 1 of the UI redesign): extended `GetTopCollectionsQuery` with one level of `children`/`featuredAsset`; desktop `navbar-collections.tsx` now renders a mega-menu dropdown for collections with children (plain link preserved for leaf collections); mobile `mobile-nav.tsx` mirrors this with an accordion. Added a shared `search-overlay.tsx` (command palette + live product suggestions via a new `getSearchSuggestions` server action reusing the existing `SearchProductsQuery`, no new GraphQL operation) wired into both desktop `search-input.tsx` and the mobile nav's search trigger. No commerce/cart/checkout/auth logic touched; `check-types`, `lint`, and `build` all pass.
